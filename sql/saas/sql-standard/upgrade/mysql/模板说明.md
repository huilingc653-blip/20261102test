# MySQL 存量升级脚本模板说明

本目录 `sql/saas/sql-standard/upgrade/mysql/` 存放**存量环境**的增量升级脚本。

与 `sql/saas/sql-standard/mysql/`（`00~08` 初始化基线，面向空库/新装）不同，本目录脚本面向**已有业务数据的环境**执行，必须可重复执行（幂等），且**禁止破坏性操作**（无条件 DROP/TRUNCATE、删表重建、无界 DELETE/UPDATE 等）。

> 维护约束：后续新增存量升级脚本统一放本目录，不再向 `sql/saas/mysql/` 源目录持续堆积 `N.DbUpdate.sql`（源目录禁止修改，仅保留历史追溯）。

## 脚本命名建议

`YYYY-MM-DD-<模块>-<变更简述>.sql`，例如 `2026-09-19-paymentlimit-新增限额规则表.sql`。

同一变更若需 MySQL/Oracle 双版本，两侧同名成对维护（Oracle 版本放 `upgrade/oracle/` 同名文件）。

## 文件头模板

每个升级脚本顶部统一带以下注释块：

```sql
-- ============================================================================
-- SaaS 存量升级脚本
-- 数据库：MySQL
-- 脚本：YYYY-MM-DD-<模块>-<变更简述>
-- 变更：<新增表/字段/索引/数据/函数视图等对象清单，及业务背景>
-- 生成日期：YYYY-MM-DD
-- 注意：面向存量环境，可重复执行；禁止反向覆盖 sql/saas/mysql 源脚本。
-- ============================================================================
```

## 场景模板

### 场景 1：新增表

规范要点：
- `-- 表说明：XXX` 紧邻 `CREATE TABLE` 上方（表说明取自表级 COMMENT）。
- 使用 `CREATE TABLE IF NOT EXISTS`，保证幂等。
- 字段四空格缩进，字段名/类型按最宽列对齐。
- 移除字段级 CHARACTER SET / COLLATE，统一到表级 `utf8mb4_bin`。
- 表级尾部固定 `ENGINE = InnoDB` + `DEFAULT CHARSET = utf8mb4` + `COLLATE = utf8mb4_bin`。
- 无值 COMMENT 不输出（避免空注释）。

```sql
-- 表说明：司库银行端限额规则主表
CREATE TABLE IF NOT EXISTS `BT_TR_LIMIT_RULE`
(
    `ID`          VARCHAR(32)   NOT NULL,
    `RULE_CODE`   VARCHAR(32)   NOT NULL,
    `RULE_NAME`   VARCHAR(128)  NOT NULL,
    `BANK_ORG_ID` VARCHAR(32)   NOT NULL,
    `TENANT_ID`   VARCHAR(32)   NOT NULL,
    `ENABLE_FLAG` CHAR(1)       NOT NULL,
    `REMARK`      VARCHAR(1000) NULL,
    PRIMARY KEY (`ID`) USING BTREE,
    UNIQUE KEY `UK_TR_LR_TEN_CODE` (`TENANT_ID`, `RULE_CODE`) USING BTREE,
    KEY `IX_TR_LR_QUERY` (`TENANT_ID`, `BANK_ORG_ID`, `ENABLE_FLAG`) USING BTREE
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_bin
  COMMENT = '司库银行端限额规则主表';
```

### 场景 2：存量表新增字段

规范要点：
- 新字段优先合并进所属 `CREATE TABLE`（场景 1）；只有存量升级才用本形式。
- 用 `INFORMATION_SCHEMA.COLUMNS` 做存在性保护。
- 禁止使用 `SAAS_ADD_COLUMN_IF_MISSING` 辅助过程。
- 存储过程用完即删（`CALL` 后 `DROP PROCEDURE IF EXISTS`）；同表多列合并进同一过程，避免重复建/删。

```sql
-- 存储过程说明：PRO_ADD_COL
DROP PROCEDURE IF EXISTS PRO_ADD_COL;
DELIMITER $$
CREATE PROCEDURE PRO_ADD_COL()
BEGIN
    IF NOT EXISTS (SELECT * FROM INFORMATION_SCHEMA.COLUMNS WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'sys_tenant_manager' AND COLUMN_NAME = 'corp_number') THEN
        ALTER TABLE sys_tenant_manager
            ADD COLUMN corp_number int(5) not null DEFAULT 100 COMMENT '单位数量';
    END IF;
END$$
DELIMITER ;
CALL PRO_ADD_COL();
DROP PROCEDURE IF EXISTS PRO_ADD_COL;
```

### 场景 3：存量表新增索引

规范要点：
- 用 `INFORMATION_SCHEMA.STATISTICS` 判断索引名是否存在。
- 存储过程用完即删；同表多索引合并进同一过程。

```sql
-- 存储过程说明：PRO_ADD_IND
DROP PROCEDURE IF EXISTS PRO_ADD_IND;
DELIMITER $$
CREATE PROCEDURE PRO_ADD_IND()
BEGIN
    IF NOT EXISTS (SELECT * FROM INFORMATION_SCHEMA.STATISTICS WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'NIS_BILLHEAD' AND INDEX_NAME = 'IDX_NIS_BILLHEAD_SPLIT_ID') THEN
        ALTER TABLE NIS_BILLHEAD ADD INDEX IDX_NIS_BILLHEAD_SPLIT_ID (SPLIT_ID);
    END IF;
END$$
DELIMITER ;
CALL PRO_ADD_IND();
DROP PROCEDURE IF EXISTS PRO_ADD_IND;
```

### 场景 4：修改字段定义

规范要点：
- `MODIFY` / `CHANGE` 本身幂等（重复执行结果一致），无需存在性保护。
- 改类型/默认值/注释用 `MODIFY COLUMN`；需改名用 `CHANGE COLUMN`。
- 不在字段级写 CHARACTER SET / COLLATE。

```sql
ALTER TABLE `bis_bank_receipt_dtl`
    MODIFY COLUMN `FILE_PATH` TEXT NULL COMMENT '文件路径';
```

### 场景 5：新增/替换函数、存储过程、视图

规范要点：
- `-- 函数说明：XXX`（视图/存储过程/触发器同理）紧邻 `DELIMITER` 上方。
- `DROP ... IF EXISTS` + `CREATE ...` 替换定义，保证幂等。

```sql
-- 函数说明：GET_TENANT_ID
DELIMITER $$
DROP FUNCTION IF EXISTS `GET_TENANT_ID`$$
CREATE FUNCTION `GET_TENANT_ID`() RETURNS varchar(32)
    DETERMINISTIC
    SQL SECURITY INVOKER
BEGIN
    DECLARE v_tenant_id varchar(32) DEFAULT NULL;
    RETURN v_tenant_id;
END$$
DELIMITER ;
```

### 场景 6：新增预置数据

规范要点：
- `INSERT IGNORE` + `SELECT ... FROM DUAL WHERE NOT EXISTS` 双重保护。
- 固定主键或明确业务唯一键，重复执行不重复插入。
- 逐条换行，不堆叠 `),(` 多值。

```sql
-- 示例一：业务唯一键保护（无固定主键时用业务键 NOT EXISTS）
INSERT IGNORE INTO bt_bank_type(ID, BANK_TYPE, TYPE_NAME, BANK_PREFIX, VALID_SIGN)
SELECT MD5(UUID()), '0001', '中国工商银行', '102', '1'
FROM DUAL
WHERE NOT EXISTS (SELECT 1 FROM bt_bank_type WHERE BANK_TYPE = '0001');

-- 示例二：固定主键 + 业务键双重保护
INSERT IGNORE INTO sys_multi_lang (ID, LANG_CODE, LANG_CONTEXT, LANG_KEY)
SELECT 'c8a1b2d3e4f5467a8b9c0d1e2f304152', 'zh_CN', '该数据暂无发行信息', 'common.noData'
FROM DUAL
WHERE NOT EXISTS (
    SELECT 1 FROM sys_multi_lang
    WHERE LANG_KEY = 'common.noData' AND LANG_CODE = 'zh_CN'
);
```

### 场景 7：更新预置数据

规范要点：
- 必须带主键/唯一键 `WHERE`，禁止无界 `UPDATE`。

```sql
UPDATE sys_multi_lang
SET LANG_CONTEXT = '更新后的文案'
WHERE LANG_KEY = 'common.noData' AND LANG_CODE = 'zh_CN';
```

### 场景 8：删除预置数据

规范要点：
- 必须带主键/唯一键 `WHERE`，禁止无界 `DELETE`。
- 业务数据删除需谨慎，优先考虑逻辑删除标志而非物理删除。

```sql
DELETE FROM sys_multi_lang
WHERE LANG_KEY = 'common.noData' AND LANG_CODE = 'zh_CN';
```

## 通用规范（硬约束）

- 四空格缩进，UTF-8 无 BOM。
- 表级 COLLATE 统一 `utf8mb4_bin`；字段级 CHARACTER SET / COLLATE 移除。
- 禁止无条件 `DROP TABLE` / `TRUNCATE TABLE` / `ALTER TABLE ... DROP` / `RENAME TABLE` / `DROP DATABASE`。
- 禁止无界 `DELETE` / `UPDATE`（必须带主键/唯一键 WHERE）。
- 禁止 `SAAS_ADD_COLUMN_IF_MISSING` 辅助过程。
- 禁止 `##GOGO` / `##GOTO` 残留。
- MySQL 与 Oracle 成对维护，业务对象保持对应；改完跑 `.aiassistant/skills/sql-standardize/scripts/Test-IdempotentSql.ps1` 门禁。
