# Oracle 存量升级脚本模板说明

本目录 `sql/saas/sql-standard/upgrade/oracle/` 存放**存量环境**的增量升级脚本。

与 `sql/saas/sql-standard/oracle/`（`00~08` 初始化基线，面向空库/新装）不同，本目录脚本面向**已有业务数据的环境**执行，必须可重复执行（幂等）。

> **关键差异**：初始化基线对 Oracle 建表采用「先 `DROP TABLE`（吞异常）再 `CREATE TABLE`」的先删后建形式，仅限空库/新装。**本目录存量升级脚本禁止先删后建**——已有业务数据的环境删表重建会丢数据，必须改用 `USER_TABLES` / `USER_TAB_COLUMNS` / `USER_INDEXES` 做存在性保护。

> 维护约束：后续新增存量升级脚本统一放本目录，不再向 `sql/saas/oracle/` 源目录持续堆积 `N.DbUpdate-oracle.sql`（源目录禁止修改，仅保留历史追溯）。

## 脚本命名建议

`YYYY-MM-DD-<模块>-<变更简述>.sql`，例如 `2026-09-19-paymentlimit-新增限额规则表.sql`。同一变更若需 MySQL/Oracle 双版本，两侧同名成对维护（MySQL 版本放 `upgrade/mysql/` 同名文件）。

## 文件头模板

```sql
-- ============================================================================
-- SaaS 存量升级脚本
-- 数据库：Oracle
-- 脚本：YYYY-MM-DD-<模块>-<变更简述>
-- 变更：<新增表/字段/索引/数据/函数视图等对象清单，及业务背景>
-- 生成日期：YYYY-MM-DD
-- 注意：面向存量环境，可重复执行；禁止反向覆盖 sql/saas/oracle 源脚本。
-- ============================================================================
```

## 场景模板

### 场景 1：新增表（先删后建，仅限新装/初始化场景）

规范要点：
- `-- 表说明：XXX` 紧邻 `BEGIN` 上方（位于 DROP 块之前）。
- `DROP TABLE`（EXCEPTION WHEN OTHERS THEN NULL 吞异常）+ 原生 `CREATE TABLE`。
- `COMMENT ON TABLE/COLUMN` 补充注释。
- 索引用原生 `CREATE INDEX`（表已 DROP 重建，索引随之重建）。

```sql
-- 表说明：票据记账信息表
BEGIN
    EXECUTE IMMEDIATE 'DROP TABLE AB_ACCBOOK_INFO';
EXCEPTION WHEN OTHERS THEN NULL;
END;
/

CREATE TABLE AB_ACCBOOK_INFO (
     ID VARCHAR2(32) NOT NULL PRIMARY KEY,
     AID VARCHAR2(32) NULL,
     NET_ID VARCHAR2(32) NULL,
     TENANT_ID VARCHAR2(32) NULL
);

COMMENT ON TABLE AB_ACCBOOK_INFO IS '票据记账信息表';
COMMENT ON COLUMN AB_ACCBOOK_INFO.ID IS '主键';
COMMENT ON COLUMN AB_ACCBOOK_INFO.AID IS '流水表ID';

CREATE INDEX IDX_AB_ACCBOOK_INFO_TENANT_ID ON AB_ACCBOOK_INFO (TENANT_ID);        
/
```

### 场景 2：存量表新增字段

规范要点：用 `USER_TAB_COLUMNS` 判断列不存在才 `ALTER TABLE ADD`；带列注释用写法一（推荐），历史修正（已存在则 MODIFY 对齐）用写法二。

```sql
-- 写法一：带列注释（推荐）
DECLARE
    v_COUNT NUMBER;
BEGIN
    SELECT COUNT(*) INTO v_COUNT
    FROM USER_TAB_COLUMNS
    WHERE TABLE_NAME = 'SYS_TENANT_MANAGER'
      AND COLUMN_NAME = 'CORP_NUMBER';
    IF v_COUNT < 1 THEN
        EXECUTE IMMEDIATE 'ALTER TABLE SYS_TENANT_MANAGER ADD (CORP_NUMBER NUMBER(10) DEFAULT 100 NOT NULL)';
        EXECUTE IMMEDIATE 'COMMENT ON COLUMN SYS_TENANT_MANAGER.CORP_NUMBER IS ''单位数量''';
    END IF;
END;
/

-- 写法二：已存在则 MODIFY 对齐（历史修正常见）
DECLARE
    cnt NUMBER;
BEGIN
    SELECT COUNT(*) INTO cnt FROM USER_TAB_COLUMNS WHERE TABLE_NAME = 'BT_BANK_ACC' AND COLUMN_NAME = 'RPA_FUNCTION';
    IF cnt = 0 THEN
        EXECUTE IMMEDIATE 'ALTER TABLE BT_BANK_ACC ADD RPA_FUNCTION VARCHAR2(60)';
    ELSE
        EXECUTE IMMEDIATE 'ALTER TABLE BT_BANK_ACC MODIFY RPA_FUNCTION VARCHAR2(60)';
    END IF;
END;
/
```

### 场景 3：存量表新增索引

规范要点：用 `USER_INDEXES` 判断索引不存在才创建。

```sql
DECLARE
    VN_COUNT NUMBER;
BEGIN
    SELECT COUNT(*) INTO VN_COUNT
    FROM USER_INDEXES
    WHERE INDEX_NAME = 'IDX_NIS_BILLHEAD_SPLIT_ID'
      AND TABLE_NAME = 'NIS_BILLHEAD';
    IF VN_COUNT = 0 THEN
        EXECUTE IMMEDIATE 'create index IDX_NIS_BILLHEAD_SPLIT_ID on NIS_BILLHEAD(SPLIT_ID)';
    END IF;
    COMMIT;
END;
/
```

### 场景 4：修改字段定义

规范要点：用 `USER_TAB_COLUMNS` 判断，已存在则 `MODIFY` 对齐（同场景 2 写法二）。

```sql
DECLARE
    cnt NUMBER;
BEGIN
    SELECT COUNT(*) INTO cnt FROM USER_TAB_COLUMNS WHERE TABLE_NAME = 'BT_BANK_ACC' AND COLUMN_NAME = 'RPA_FUNCTION';
    IF cnt = 0 THEN
        EXECUTE IMMEDIATE 'ALTER TABLE BT_BANK_ACC ADD RPA_FUNCTION VARCHAR2(60)';
    ELSE
        EXECUTE IMMEDIATE 'ALTER TABLE BT_BANK_ACC MODIFY RPA_FUNCTION VARCHAR2(60)';
    END IF;
END;
/
```

### 场景 5：新增/替换函数、存储过程、视图

规范要点：`-- 函数说明：XXX`（视图/存储过程同理）紧邻 `CREATE OR REPLACE` 上方；`CREATE OR REPLACE` 替换定义保证幂等。

```sql
-- 函数说明：BT_ABS
CREATE OR REPLACE FUNCTION BT_ABS (in_str1 in number) return number is
    vn_result number;
begin
    vn_result := abs(in_str1);
    return(vn_result);
end;
/
```

### 场景 6：新增预置数据

规范要点：优先用 `INSERT /*+ IGNORE_ROW_ON_DUPKEY_INDEX ... */` 提示（依赖目标表唯一索引）并带 `NOT EXISTS` 兜底；无提示时用 `DUP_VAL_ON_INDEX` 捕获；日期/时间戳字段用 `TO_DATE('...','yyyy-mm-dd hh24:mi:ss')` 或 `TIMESTAMP '...'`，禁止裸字符串字面量。

```sql
-- 写法一：IGNORE_ROW_ON_DUPKEY_INDEX 提示（有唯一索引时）
INSERT /*+ IGNORE_ROW_ON_DUPKEY_INDEX (sys_multi_lang (ID)) */ INTO sys_multi_lang (ID, LANG_CODE, LANG_CONTEXT, LANG_KEY)
SELECT '1f9c13e3924911f19fca005056b97e85', 'zh_CN', '未找到注册回调服务请检查配置或者路径', 'workflow.no.complete.err' FROM DUAL
WHERE NOT EXISTS (SELECT 1 FROM sys_multi_lang WHERE LANG_KEY = 'workflow.no.complete.err' AND LANG_CODE = 'zh_CN');

-- 写法二：DUP_VAL_ON_INDEX 捕获（无提示可用时）
BEGIN
    INSERT INTO some_table (PK, COL) VALUES ('fixed-pk', 'value');
EXCEPTION
    WHEN DUP_VAL_ON_INDEX THEN NULL;
END;
/
```

### 场景 7：更新预置数据

规范要点：必须带主键/唯一键 `WHERE`，禁止无界 `UPDATE`。

```sql
UPDATE sys_multi_lang
SET LANG_CONTEXT = '更新后的文案'
WHERE LANG_KEY = 'common.noData' AND LANG_CODE = 'zh_CN';
COMMIT;
```

### 场景 8：删除预置数据

规范要点：必须带主键/唯一键 `WHERE`，禁止无界 `DELETE`；业务数据删除需谨慎，优先逻辑删除。

```sql
DELETE FROM sys_multi_lang
WHERE LANG_KEY = 'common.noData' AND LANG_CODE = 'zh_CN';
COMMIT;
```

## 通用规范（硬约束）

- 四空格缩进，UTF-8 无 BOM。
- 存量升级**禁止**先删后建（`DROP TABLE` 重建），改用 `USER_TABLES` / `USER_TAB_COLUMNS` / `USER_INDEXES` 存在性保护。
- 日期/时间戳字段禁止裸字符串字面量，统一 `TO_DATE` / `TIMESTAMP` 字面量；口径与门禁一致（见 `Oracle-DateLiterals.ps1`）。
- 禁止无界 `DELETE` / `UPDATE`（必须带主键/唯一键 WHERE）。
- 禁止 `##GOGO` / `##GOTO` 残留。
- MySQL 与 Oracle 成对维护，业务对象保持对应；改完跑 `.aiassistant/skills/sql-standardize/scripts/Test-IdempotentSql.ps1` 门禁。
